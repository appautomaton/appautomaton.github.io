# Boustrophedon

A motion study for the home page. Not wired into the build, not deployed, not
linked from anywhere.

## Look at it

```sh
python3 -m http.server 8932   # from the repo root
open http://127.0.0.1:8932/prototypes/boustrophedon/
```

Fonts and plates are read from `src/`, so nothing here duplicates a binary.
`index.html` is generated by `build.mjs` from `../catalog.snapshot.json`, which
was exported from `src/data/catalog.ts`. Regenerate with `node build.mjs`.

## The idea

Boustrophedon is how early Greek inscriptions were cut: one line runs right,
the next turns and runs left, as an ox plows a field. Each shelf becomes a
horizontal band, and the bands alternate direction. The fourth shelf holds one
project, so it stops being a band and becomes a coda instead.

Four techniques, one metaphor. A sheet of paper pulled through a press.

- **The bands travel** on the act's own view timeline, sticky while they run.
- **The plates engrave themselves** as the band travels: a repeating hatch
  serves as a mask, and its line weight climbs from 0 to 8px. Cross-hatching is
  how an engraver builds tone, so the reveal is the medium describing itself.
- **Scroll speed** feeds `--vel-abs`, which narrows the variable width axis of
  League Gothic. Kept to about a third of what reads as an effect: it should be
  the grain of the paper, not a trick.
- **The margin** carries registration marks and a run indicator, which is the
  only part of this that is navigation rather than atmosphere.

## What it must not cost

Everything above happens in the presentation layer. The rules the prototype was
written against, and the measurements that hold them:

| Rule | Measured on the generated file |
| --- | --- |
| DOM order is reading order | `h1 → h2 h3×6 → h2 h3×6 → h2 h3×7 → h2 h3` |
| Every unit is a real link | 20 `<a href>`, 15 on this domain |
| Nothing is injected by script | 723 readable words with JS off |
| Structured data is intact | 22 JSON-LD nodes |

Act II reads right to left on screen. In the document its heading is still
followed by its six units in a straight line. `flex-direction: row-reverse`
does the turning, and it moves nothing out of flow.

Without scroll-driven animation support, or under
`prefers-reduced-motion: reduce`, the bands become wrapping grids: `sticky`
falls back to `static`, `nowrap` to `wrap`, the transform drops, and the
reversed band returns to `row`. All twenty units stay visible either way.

## A trap worth remembering

The plates first used `view()` for the hatch reveal, which froze at 7.3 of 8px
and never finished. A card inside a sticky band travels horizontally while its
vertical position holds still, so a view timeline sees no progress to report.
The fix was not a different range but a different clock: the hatch now runs on
the act's timeline, so the whole band engraves as it is drawn across. The band,
not the card, turned out to be the right unit.

For the same reason the band cards carry no press-in animation. Travelling
across the screen is already their entrance. The press is kept for the coda and
for the fallback grid, where arrival really is vertical.

## Before this could ship

- The live page is React 19 with StyleX and `@astryxdesign/core`. This is plain
  CSS. Either the components adopt these rules or the prototype is rebuilt in
  the existing vocabulary.
- `scripts/prerender.mjs` asserts the rendered card count against the catalog
  and builds `sitemap.xml` from the links the page renders. Both survive this
  layout, because the links and the count are unchanged, but both need
  rechecking against the real markup.
- Cross-document view transitions are opted into here. On this domain the hub
  and all fifteen project pages are same origin, so the morph would work once
  deployed. Each project page has to carry `@view-transition` as well.
